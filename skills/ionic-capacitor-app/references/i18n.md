# i18n: lingue, persistenza, fallback

Fonti: ngx-translate <https://ngx-translate.org/getting-started/installation/> e
<https://ngx-translate.org/reference/translate-service-api/>, migrazione v18
<https://ngx-translate.org/getting-started/migration-guide/>, react-i18next
<https://react.i18next.com/>, i18next <https://www.i18next.com/>, vue-i18n
<https://vue-i18n.intlify.dev/guide/>.

## Principi (tutti i framework)

- Le **lingue** e la lingua **principale** (= fallback) le decide il progetto. Non
  hardcodare elenchi o default arbitrari: definisci una costante `SUPPORTED_LANGS` e
  `FALLBACK_LANG` in un solo posto, popolate con quanto detto dall'utente.
- Lingua all'avvio, in ordine: (1) valore salvato in Preferences (`lang`), (2) lingua del
  dispositivo se supportata (`navigator.language` senza regione), (3) fallback.
- Il valore salvato va **riletto prima del primo render** (era un bug: salvato ma mai
  riletto). Il cambio lingua dalle Impostazioni aggiorna l'i18n **e** salva.
- Chiavi annidate per area (`tabs.home`, `settings.theme`, `errors.network`); nessuna
  stringa visibile hardcoded nei template; plurali e interpolazioni con l'API della
  libreria; date e numeri con `Intl.DateTimeFormat`/`Intl.NumberFormat` sulla lingua
  corrente.
- File: `src/assets/i18n/<lang>.json` (Angular, serviti via HTTP) oppure importati come
  moduli (React/Vue). Un file per lingua, stesse chiavi in tutti.
- Testi **nativi** (dialoghi di permesso iOS): `InfoPlist.strings` per lingua in Xcode;
  Android usa `res/values-<lang>/strings.xml`. Da fare solo per le lingue supportate.

Struttura di esempio (le chiavi sono indicative):

```json
{
  "tabs": { "home": "...", "settings": "..." },
  "settings": { "title": "...", "language": "...", "theme": "...", "themeSystem": "...", "themeLight": "...", "themeDark": "...", "notifications": "..." },
  "common": { "ok": "...", "cancel": "...", "retry": "..." },
  "errors": { "network": "..." }
}
```

```ts
// src/core/lang.ts (condiviso)
import { Preferences } from '@capacitor/preferences';

export const SUPPORTED_LANGS = ['xx', 'yy'] as const;   // dal progetto
export type Lang = (typeof SUPPORTED_LANGS)[number];
export const FALLBACK_LANG: Lang = 'xx';               // dal progetto
const KEY = 'lang';

export async function resolveInitialLang(): Promise<Lang> {
  const { value } = await Preferences.get({ key: KEY });
  if (value && (SUPPORTED_LANGS as readonly string[]).includes(value)) return value as Lang;
  const device = navigator.language?.split('-')[0];
  return (SUPPORTED_LANGS as readonly string[]).includes(device) ? (device as Lang) : FALLBACK_LANG;
}

export const persistLang = (lang: Lang) => Preferences.set({ key: KEY, value: lang });
```

## Angular: ngx-translate 18

Verificato: `@ngx-translate/core` e `@ngx-translate/http-loader` **18.0.x** (Angular ≥ 18).
Cambiamenti rispetto alle versioni precedenti: `TranslateModule` **rimosso**;
`provideTranslateService({...})` con `loader: provideTranslateHttpLoader({...})`;
`defaultLanguage`/`setDefaultLang` → `fallbackLang`/`setFallbackLang`; `currentLang` è un
**signal** (`translate.currentLang()`); nei componenti si importano `TranslatePipe` e
`TranslateDirective`.

```bash
npm i @ngx-translate/core@18 @ngx-translate/http-loader@18
```

```ts
// src/main.ts (providers)
import { provideHttpClient } from '@angular/common/http';
import { provideTranslateService } from '@ngx-translate/core';
import { provideTranslateHttpLoader } from '@ngx-translate/http-loader';
import { FALLBACK_LANG } from './app/core/lang';

providers: [
  provideHttpClient(),
  provideTranslateService({
    fallbackLang: FALLBACK_LANG,
    loader: provideTranslateHttpLoader({ prefix: './assets/i18n/', suffix: '.json' }),
  }),
  provideAppInitializer(() => inject(LanguageService).init()),   // inject() sincrono, poi la promessa
]
```

Con più servizi nello stesso initializer acquisiscili tutti **prima** del primo `await`
(vedi `angular.md`, NG0203).

```ts
// src/app/core/language.service.ts
import { Injectable, inject } from '@angular/core';
import { TranslateService } from '@ngx-translate/core';
import { firstValueFrom } from 'rxjs';
import { Lang, persistLang, resolveInitialLang } from './lang';

@Injectable({ providedIn: 'root' })
export class LanguageService {
  private readonly translate = inject(TranslateService);
  readonly current = this.translate.currentLang;        // Signal<string | null>

  async init() {
    await firstValueFrom(this.translate.use(await resolveInitialLang()));
  }

  async set(lang: Lang) {
    await firstValueFrom(this.translate.use(lang));
    await persistLang(lang);
  }
}
```

Nel template: `{{ 'settings.title' | translate }}` (con `TranslatePipe` negli `imports`),
`{{ 'greeting' | translate: { name } }}` per l'interpolazione; in TypeScript
`translate.instant('key')` solo dopo il caricamento, altrimenti `translate.get('key')`.
Il file JSON deve stare dove `angular.json` serve gli asset (nello starter Ionic:
`src/assets/i18n/`), così `./assets/i18n/<lang>.json` risponde sia in `ionic serve` sia
dentro Capacitor.

## React: i18next 26 + react-i18next 17

```bash
npm i i18next@26 react-i18next@17
```

```ts
// src/i18n/index.ts
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import { FALLBACK_LANG, Lang, persistLang, resolveInitialLang } from '../core/lang';
import xx from './xx.json';        // un import per lingua supportata
import yy from './yy.json';

export async function initI18n(): Promise<void> {
  const lng = await resolveInitialLang();
  await i18n.use(initReactI18next).init({
    resources: { xx: { translation: xx }, yy: { translation: yy } },
    lng,
    fallbackLng: FALLBACK_LANG,
    interpolation: { escapeValue: false },
  });
}

export async function changeLang(lang: Lang): Promise<void> {
  await i18n.changeLanguage(lang);
  await persistLang(lang);
}

export default i18n;
```

`await initI18n()` in `bootstrap()` prima di `createRoot(...).render(...)` (vedi
`react.md`). Nei componenti `const { t, i18n } = useTranslation()`; `i18n.language` per la
lingua corrente; `t('key', { count })` per i plurali (JSON v4: chiavi `key_one`, `key_other`).

## Vue: vue-i18n 11

```bash
npm i vue-i18n@11
```

```ts
// src/i18n/index.ts
import { createI18n } from 'vue-i18n';
import { FALLBACK_LANG, Lang, persistLang, resolveInitialLang } from '@/core/lang';
import xx from './xx.json';
import yy from './yy.json';

export async function createAppI18n() {
  return createI18n({
    legacy: false,                       // solo Composition API (legacy rimossa in v12)
    locale: await resolveInitialLang(),
    fallbackLocale: FALLBACK_LANG,
    messages: { xx, yy },
  });
}

export async function changeLang(i18nGlobal: { locale: { value: string } }, lang: Lang) {
  i18nGlobal.locale.value = lang;
  await persistLang(lang);
}
```

Nei componenti `const { t, locale } = useI18n()`; per cambiare lingua dalle Impostazioni
`locale.value = lang` + `persistLang(lang)`. `$t` nei template funziona con
`globalInjection` (default `true` in v11).

## Selettore lingua (Impostazioni)

`ion-select` con un'opzione per lingua supportata, etichetta nella lingua stessa (endonimo,
es. "Deutsch"), valore = codice; `ionChange` → `set(lang)`. Dopo il cambio, i testi
aggiornano da soli (pipe/hook reattivi); i dati caricati con testi localizzati dal backend
vanno ricaricati.
